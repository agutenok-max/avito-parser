# Развёртывание — справочник

> 📱 **Простая пошаговая инструкция для iPhone — [IPHONE_START.md](IPHONE_START.md).**
> Этот файл — подробности для понимания и решения проблем.

## Почему Amvera

Avito ограничивает доступ с зарубежных серверов и многих адресов дата-центров. При подготовке
проекта это проверено: с облачного сервера в США Avito отвечает «Доступ ограничен: проблема с IP»
(HTTP 429/439) и на обычный запрос, и на запрос настоящего браузера Chromium.

**Amvera Cloud** — российский хостинг с Docker, постоянным хранилищем `/data`, переменными/секретами
и автодеплоем из GitHub; управляется через сайт с телефона. Конфигурация — `amvera.yml` в корне.

Даже с российского IP Avito может временно ограничивать доступ. Бот это распознаёт и делает паузу;
обходить защиту (капчи и т.п.) он не пытается.

## Что настроено в репозитории

| Что | Где | Значение |
|---|---|---|
| Сборка | `Dockerfile` | Python 3.12-slim + зависимости + headless Chromium (Playwright) |
| Команда запуска | `Dockerfile` (CMD) | `python -m telegram_bot.bot` |
| Порт | `amvera.yml` → `containerPort: 8080` | приложение слушает 8080 (и `$PORT`, если задан) |
| Health check | `GET /health` | `200 {"status":"ok"}`, если мониторинг жив; иначе `503` |
| Постоянное хранилище | `amvera.yml` → `persistenceMount: /data` | `DATA_DIR=/data`: база `/data/avito_bot.db`, логи `/data/logs/` |
| Перезапуск | Amvera перезапускает приложение при выходе | + внутренний сторож: если мониторинг завис > 20 мин, процесс завершается и перезапускается |
| Автодеплой | вебхук GitHub → Amvera | push в `main` → сборка и запуск |

Проверено в Docker (локально и в GitHub Actions): образ собирается, Chromium запускается,
бот без токена завершается с понятной ошибкой, неверный токен — ошибка 401 без вывода токена,
база в смонтированном `/data` сохраняется между перезапусками контейнера, `/health` отвечает на 8080.

### Память

Замеры в Docker-контейнере:
- бот в простое — ~45 МБ, во время обычных HTTP-проверок — до ~90 МБ;
- Chromium (Playwright) с тяжёлой страницей каталога (200 карточек) — пик ~225 МБ;
- с лимитом **500 МБ** Chromium отработал 3 раза подряд без ошибок; с лимитом **100 МБ** — не запускается.

Chromium запускается только если Avito отдал страницу без списка объявлений
(при блокировке по IP — не запускается), поэтому большую часть времени бот занимает < 100 МБ.

| Тариф Amvera | Память | Цена / 30 дней | Рекомендация |
|---|---|---|---|
| Пробный | 100 МБ | 170 ₽ | не подходит |
| Начальный | 500 МБ | 290 ₽ | ✅ достаточно (`FETCH_MODE=auto` по умолчанию) |
| Начальный Плюс | 1 ГБ | 490 ₽ | ✅ с запасом |

Если на «Начальном» в логах появятся перезапуски из‑за памяти — добавьте переменную
`FETCH_MODE` = `http` (браузер не используется) или перейдите на «Начальный Плюс».

### SQLite и постоянное хранилище

- База лежит в `/data` — Amvera сохраняет эту папку при перезапусках и пересборках.
- Журнал SQLite по умолчанию `DELETE` (надёжен на сетевых дисках), запись `synchronous=FULL`.
- При старте бот проверяет, что `/data` — подключённый том, и пишет в лог
  `Постоянное хранилище подключено: /data` (или предупреждение). То же видно в боте: `/status`.
- Скачать резервную копию базы можно в Amvera: вкладка «Репозиторий» → папка Data → `avito_bot.db`.

## Как бот получает объявления

1. Ссылка нормализуется: `m.avito.ru` → `www.avito.ru`, удаляются номер страницы и старая сортировка,
   добавляется `s=104` (сортировка «по дате»). Путь и все фильтры (`q`, `pmin`, `pmax`, `f`, радиус и др.)
   сохраняются — работает любая категория.
2. Загрузка страницы обычным HTTP-запросом; если пришла страница без списка объявлений —
   headless Chromium (`FETCH_MODE=auto`).
3. Разбор: HTML-карточки `data-marker="item"` + встроенный JSON Avito
   (`<script type="mime/invalid" data-mfe-state="true">`, а также старый `__initialData__`):
   ID, название, цена, адрес, описание, фото и точное время публикации (`sortTimeStamp`).
   Если точного времени нет — берётся текст с карточки («5 минут назад»); если нет ничего — бот пишет
   «не указана», а не выдумывает дату.
4. Новые = ID, которых ещё нет в базе для этого поиска (`UNIQUE(search_id, item_id)`).
   Объявление записывается до отправки, после успешной отправки помечается «отправлено».
   Ошибка Telegram → до 3 повторов при следующих проверках.
5. Если вся первая страница новая (например, после долгой паузы), проверяется следующая страница.
6. Отправка: самые свежие первыми, не больше 10 за раз на поиск (остальные — одной сводкой со ссылкой).

Загрузка устойчива к сбоям: временная сетевая ошибка (сброс соединения, таймаут DNS) повторяется
один раз; браузер ждёт появления списка объявлений или встроенного JSON (до 20 с) и имеет общий
таймаут 60 с. Повторов при блокировке нет — чтобы не нагружать Avito.

**Различение ответов Avito.** Бот различает и по-разному реагирует на:
- `403` / «Доступ ограничен» → блокировка доступа по IP (пауза);
- `429` / `439` → ограничение частоты запросов (пауза, совет увеличить интервал);
- CAPTCHA / проверка робота → блокировка (пауза; защита **не обходится**);
- сетевую ошибку → один повтор, затем сообщение об ошибке;
- пустую выдачу («ничего не найдено») → это не ошибка, просто 0 новых объявлений.

Причину последнего ограничения видно в `/status` и в команде `/diagnose`.

**Адаптивный интервал.** Чтобы не нагружать Avito, когда новых объявлений долго нет, интервал
автоматически растёт (до `ADAPTIVE_MAX_INTERVAL_MINUTES`, по умолчанию 20 мин) и мгновенно
возвращается к заданному вами, как только появляется новое объявление. Никогда не опускается ниже
вашего интервала. Отключается переменной `ADAPTIVE_INTERVAL=false`.

## Можно ли использовать официальный API Avito

Коротко: для этой задачи — нет. Официальный API Avito (`api.avito.ru`, регистрация приложения в
личном кабинете → «Настройки → Avito API») предназначен для работы с **собственными** объявлениями
и бизнес-аккаунтом продавца: автозагрузка, мессенджер, статистика, доставка, продвижение.
Публичного метода «искать чужие объявления по ссылке поиска» в нём нет, а именно это делает бот
(следит за появлением новых объявлений других продавцов). Поэтому бот читает обычные страницы поиска,
как это делает браузер. Если у вас есть бизнес-аккаунт и задача изменится на управление своими
объявлениями — тогда имеет смысл перейти на официальный API; текущий бот под это не рассчитан.

## Чего бот сознательно НЕ делает

Бот **не обходит** защиту Avito: не решает CAPTCHA, не подменяет браузерный отпечаток для обмана
антибота, не ротирует прокси для уклонения от ограничений. Это обход защитных механизмов чужого
сайта. При блокировке бот делает паузу и честно сообщает причину.

## Если Avito блокирует

Сообщение «⛔ Avito временно ограничил доступ» — бот сам ждёт 15 → 30 → 60 → 120 минут и повторяет.

1. Увеличьте интервал: `/interval 10` или `/interval 15`.
2. Уменьшите число поисков.
3. Если блокировка не проходит часами — IP сервера заблокирован. Варианты: другой российский
   хостинг/VPS или собственный HTTP-прокси в России (`PROXY_URL`). Используйте только прокси,
   которыми вы законно владеете или пользуетесь по договору.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| В логе `Не задан TELEGRAM_BOT_TOKEN` | Добавьте секрет `TELEGRAM_BOT_TOKEN`, перезапустите |
| В логе `Telegram отклонил токен (401)` | Токен скопирован с ошибкой или отозван — получите новый у @BotFather (`/token`) |
| Бот отвечает «Бот ещё не привязан к владельцу» | Добавьте `TELEGRAM_ADMIN_ID` и перезапустите |
| Бот отвечает «Это личный бот» | В `TELEGRAM_ADMIN_ID` указан другой ID |
| `/status`: «постоянное хранилище НЕ подключено» | Проверьте, что `amvera.yml` в корне и содержит `persistenceMount: /data`; пересоберите |
| В логе `Conflict: terminated by other getUpdates request` | Бот с этим токеном запущен где-то ещё (например, второй хостинг). Оставьте один |
| Нет уведомлений, но поиск подключён | Новых объявлений нет; проверьте `/status` (время последней проверки) и ссылку поиска |

## Альтернатива: собственный VPS (нужен терминал)

```bash
git clone https://github.com/agutenok-max/avito-parser.git && cd avito-parser
cp .env.example .env && nano .env      # TELEGRAM_BOT_TOKEN, TELEGRAM_ADMIN_ID
docker compose up -d --build
docker compose logs -f
curl http://127.0.0.1:8080/health
# обновление: git pull && docker compose up -d --build
```

База и логи — в `./data`, перезапуск `restart: unless-stopped`.
